# Coding-based Data Video Benchmark：Ground Truth 与评测方案

版本：设计稿 1.0 · 2026-09-17  
范围：LLM / Agent 根据结构化数据和 intent，通过编写代码生成 narration 与 data video。  
状态：可供标注与实现的协议建议；不是已经实现或验证过的评测系统。本文中的数值案例均为人为构造示例，不是实验结果。

> 当前 V1–V4 实验以 [`evaluation_contract_v2_20261105.md`](evaluation_contract_v2_20261105.md)
> 为执行契约。本文件保留协议设计与历史定义；两者冲突处，以 v2 契约和对应版本的输入契约文件为准。

## 0. 核心决策

**Ground truth 不应是一份必须复刻的 narration、D3 代码或视频，而应是一组由输入支持的任务要求、可执行事实依据、视觉证据要求与时间关系。**

- 生成端拿到：table、schema、intent、目标受众、时长约束、公开输出规范。
- 评测端持有：必需内容的语义判据、数据查询与计算、合理表达的判定规则、参考视频/SVG 辅助标注。
- 模型可自主选择：旁白措辞、图表设计、镜头、配色、分镜和非必要内容。
- 评分以最终运行结果为准：正确代码或正确计划不能替代正确画面。
- 精确数据计算交给程序；复杂语义、可读性和表达质量交给经人工校准的裁判；不假定任意 D3 都能被完全解析。
- 主榜不做风格相似度，不以源码相似度评分，不要求与原视频在相同秒数出现相同元素。

建议第一版采用 HTML/CSS/JavaScript + SVG 的 coding 赛道，允许 D3，但不强制某种绘图模板。Canvas、WebGL、Manim 等可后续增加适配器；这属于实现收敛建议，并非用户已经选定的限制。仅提交像素生成模型产出的 MP4，不属于本 benchmark。

## 1. 任务与公平比较契约

### 1.1 输入

每个样本公开以下字段：

| 字段 | 含义 | 约束 |
|---|---|---|
| table | 一张或多张结构化数据表 | 原始数值不由模型猜测；提供稳定行键 |
| schema | 字段类型、单位、空值、时间粒度、统计口径 | 不得把必要口径藏在评测端 |
| intent | 希望回答的问题与传播目标 | 明确范围，不泄露计算答案 |
| audience | 受众，例如一般公众 | 用于解释术语和阅读难度评判 |
| duration | 目标时长及公开容差 | 防止无限加长以覆盖全部内容 |
| constraints | 必需内容、数据来源限制、语言、画幅等 | 可评分的任务义务必须能从这里或 intent 推出 |
| runtime_contract | 运行环境与提交规范 | 对所有模型相同 |

主任务建议只允许基于输入表作事实论述，不开放网络检索；否则需要额外定义外部证据来源与事实真值。意图要求因果解释但输入只有描述性数据时，应修改任务或允许明确表述证据不足，不能逼模型编原因。

### 1.2 输出

必交三类产物：

1. 可执行代码及本地资源：例如 entry.html、JavaScript、样式文件。
2. narration 分段文本：用于统一语音生成；最终以实际播放的音轨为评测依据。
3. manifest：入口、所需资源、运行时 API、时长等技术信息。

可选提交 evidence_map：声明图元与数据字段/计算的关联，用于辅助定位。该文件是模型陈述，不是可信证明；缺少它不应在主质量分中直接扣分。模型提供的元素名、data-value、claim ID 都要与实际结果交叉检查。

中间 plan 可用于诊断，不强制所有系统采用同一叙事规划格式。benchmark 不应通过固定 DVSpec 模板预先替模型解决数据分析、图表编码或动画编排。

coding 边界必须可审计：禁止用薄层 HTML/JavaScript 播放预制完整成片来满足接口。提交代码须实际定义数据变换、图形呈现与时间编排；允许声明来源的装饰资源，不允许用完整预渲染数据视频替代主体实现。保留生成过程、工具调用与资源来源记录，并抽查代码职责。仅有代码文件并不能证明生成过程符合赛道要求。

### 1.3 统一 TTS，保留叙事自由

推荐首版由模型自行写 narration，使用统一语音服务/版本/音色/语速生成音频。系统可拿到句子或词级时间戳后继续写动画代码，但不得收到隐藏评分反馈。统一的是声音条件，不是旁白内容。

- 音频由评测环境按提交文本生成或复现，音轨与动画使用相同时间轴。
- narration 改动会改变时长，系统需重新获取时间线；调用和重试纳入预算。
- 语音音色自然度不列为模型生成能力；旁白内容、节奏安排和音画关系仍计分。
- ASR/强制对齐可能犯错。数字读音、同音词等歧义应人工复核，不能自动归咎于生成器。

若暂时只能让系统自带 TTS，也可运行，但需记录语音配置，并承认跨系统音质与时长存在混杂，不与统一 TTS 赛道混排。

### 1.4 生成预算

固定并记录模型版本、提示词、允许调用数/重试数、token 与执行预算、可用工具、依赖版本、分辨率与帧率。单次生成和多轮调试可设不同配置，不能把无限修复 Agent 与一次性生成混为同一预算。输出格式、时长容差、事实核验政策和评分定义均应公开。

## 2. Ground truth 的分层结构

### 2.1 五层 GT，以及明确不是 GT 的材料

| 层 | 内容 | 作用 | 是否给生成模型 |
|---|---|---|---|
| G0 数据事实基础 | table、schema、单位、来源质量、可执行查询/计算 | 确认陈述是否有据 | table/schema 公开；答案与查询标注留评测端 |
| G1 任务义务 | 必需语义单元、可替代表达、权重与适用条件 | 防止少讲刷正确率 | 义务公开可推知；具体答案和匹配记录不提供 |
| G2 视觉证据规范 | 每个必需单元需要怎样的可观察证据 | 判定真正视觉化，而非只念字幕 | 通用规则公开；样本级实例标注留评测端 |
| G3 时间关系规范 | 与生成旁白的对应关系、必要先后、可读时间 | 判定在需要时出现正确证据 | 规则公开，不提供原视频绝对时间作为答案 |
| G4 人工验证集 | 实际模型输出的事实标签、位置、时间窗、评分与分歧裁决 | 校准自动评测器 | 开发集公开；测试裁决独立保留 |

原视频、参考 narration、抽取 SVG 是 reference assets，用于提出标注候选、定位图元和制作诊断样本。它们不能自动替代 G0–G3，也不保证自身没有错误。G4 需要在获得生成结果后建立，不可能完全从参考视频预先制作出来。

**G1 按输入契约分开建立。** "模型必须讲清什么"取决于它拿到了什么输入，因此每个契约各有一份 G1（文件命名 `g1_draft_<契约>.json`）：

| 契约 | 输入 | G1 的确定方式 |
|---|---|---|
| B1 | table | 无法事先枚举单元；只要求"至少一个由表支持的定量发现及其视觉证据"，主指标转为事实 precision |
| B2 | table + intent | 按 §2.4 从 intent 拆槽、从 table 填单元；数量由 intent 决定，不预设条数（当前已起草 340 条） |
| B3 | + narration 文本 | 单元 = 旁白明确陈述的量化事实（任务即把给定旁白可视化） |
| B4 | + narration + 设计 | 同 B3，另加风格义务（风格只进人评，不进完成度） |
| B5 | 只有图 | 单元 = 参考图里可见的量化信息，需先完成表/图一致性核验 |

起草 G1 时可以看 narration 作为参考，但**判 required 只能依据该契约公开的输入**（B2 即 intent + table），否则会把原作者的取舍偷渡成隐藏要求。

> 编号变更（2026-10-12）：契约已改为 V1–V4，见 `INPUT_CONTRACTS_V2.md`。上表 B1–B5 是历史编号，对应关系为 B2 ≈ V1、B3 ≈ V2、B4 ≈ V4；B1、B5 作废。V3（加参考图、不给旁白）为新档。G1 的判定规则四档通用，只有"哪些输入算公开"不同。

### 2.2 “隐藏答案”不等于“隐藏要求”

禁止根据原视频暗中增加模型不知道的义务。例如 intent 只要求“比较两个区域”，原视频顺便谈了某个异常年份，不能因此规定所有生成视频都必须讲那个年份。

推荐把 requirements 分成：

- required：由公开 intent/constraints 明确推出，进入覆盖率分母。
- optional_valid：正确且相关的可选内容；不讲不扣分。
- unsupported_or_forbidden：无依据的因果、外推、错误统计口径等；说了要核验并标记。

如果 intent 是很开放的“挑一个值得讲的发现”，不存在唯一的必讲事实。此类样本应单独作为开放发现子集：可以要求“至少一个有支持的定量发现及其证据”，但不能用原作者的 insight 集合计算封闭 recall。首版主榜建议用范围明确、允许多种表达的 intent，而不是无限开放的故事创作。

### 2.3 不枚举所有正确答案：用接受条件

对于“比较 A 与 B 的增长表现”，可接受：

- 直接比较增长率；
- 在初值相同的前提下比较增量；
- 展示两者起终值，并明确说明哪个增长更快；
- 其他能够用表中数据证明且符合意图的表达。

把这些理解成满足语义条件的多种实现，而不是仅对几个固定字符串做匹配。对于候选表述未列在参考库中，但可被验证且满足原有公开语义条件的，应接受，并留审计记录。不能看到某个模型答案后才悄悄修改任务义务或只给该模型加例外。

### 2.4 G1 必需语义单元：定义、判定与反例（2026-10-19 修订）

旧版只写了"3–5 个必需单元"加一个示例表，没有给判定规则：什么算**一个**单元、什么算**必需**、两条单元**什么时候算重复**，全凭标注者把握。后果可以量化：50 条抽样里 237 个单元中有 63 个（27%）与同一 clip 的另一条共用同一组数据点，落在 31 条 clip 上。按本节重跑同样 50 条后是 88 个单元、0 条重复。本节把三件事定死。

#### 2.4.0 什么算"必需"：定义先于四条判定

**定义（必需性）。** 给定公开输入 I，以及由 I 确定的 intent，命题 P 是**必需的**，当且仅当：

> 任何作品，只要没有让观众获得 P，就没有完成 intent。

这就是"如果视频没有这个单元，就无法完成 intent"。一个 G1 单元，就是一条必需命题连同它的依据 B 和证据 E（结构见 2.4.1）。它有三条推论：

1. **必需性是相对 intent 的，不是相对 G0 的。** G0 里有几十条真事实，只有 intent 点到的才进 G1。
2. **必需性是对"任何作品"说的，不是对原视频说的。** 原视频讲了什么不构成义务（见 2.2）。
3. **必需性只看信息有没有被获得**，不看媒介：旁白说到、可读标注写出、图形直接呈现都算；具体证据条件归 G2，时间归 G3。

**G1 和 G0 是什么关系。** 三处接口，缺一不可：

| 接口 | G0 提供什么 | G1 怎么用 |
|---|---|---|
| 依据 | 表里的格子与可执行计算 | 单元的 B 必须落在 G0 条目上，不能是标注者心里的数 |
| 真值 | 每个命题的真假 | C1 用 G0 判真；G0 判不出的命题不是单元 |
| 词表 | 实体、人群、时间、单位、聚合口径 | 单元的主语和限定词只能用 G0 的域 |

但 **G0 不生产 G1**：G0 回答"世界上有哪些事实"，intent 回答"这次必须讲哪几条"。用集合写：

> G1 = { P : P 可由 G0 判定为真 } ∩ { P : 没有 P 就完不成 intent }

第一项是可行性（G0 管），第二项是必要性（intent 管）。两项都成立才是单元；只有第一项成立的是 optional_valid 或噪音。**所有 GT 都为 intent 服务，指的就是第二项。**

**限定词（scope）算在哪。** 每个单元除了 P 还有一组限定词 Q：人群/实体、时间窗、单位、聚合口径。Q 不是独立单元，它是 P 的一部分；判"讲到了"时 Q 必须一起被表达。判 Q 是否必需的方法：把 Q 从 P 里删掉得到 P′，如果 P′ 变成另一个 G0 不支持、或不再满足 intent 的命题，Q 就是必需的。

以 bar_34 为例。intent 是"美国人因费用跳过服药的比例最高，尤其是没有保险的"，表里的实体是六个其他国家加"有保险的美国 / 无保险的美国"。

- P₁ = "美国无保险人群因费用跳过服药的比例是 33.5%，高于表中其他所有国家"；Q₁ = {人群: 美国无保险；口径: 因费用跳过服药；单位: %}。
- 若视频只说"无保险人群最容易跳过服药"，人群被放大到全球，G0 不支持、intent 也没完成 → Q₁ 必需。
- 若视频只说"33.5% 的人因费用跳过服药"，实体整个丢了，P 不成立 → 更不算完成。

所以 "Americans" 确实进 G1，但它是**单元内部的限定词**，不是额外一条"本图讲的是美国人"的单元。单列出来就会退回 bar_27 旧稿 U1 那种表头式空话（见 2.4.6）。这条规则也说明，旧稿里大量 `identity_or_series` 单元为什么站不住。

#### 2.4.1 单元的内部结构：P、B、E 与限定词 Q

给定该档的公开输入 I（V1 = intent + table + chart_spec；V2 再加 narration；V3 再加 svg；V4 全给），**G1 的一个单元是一个三元组**

> u = (P, B, E)

| 成分 | 是什么 | 不许是什么 |
|---|---|---|
| **P 命题** | 一句关于数据的断言：主语是表里的实体/序列/时点，谓语是**比较、变化、趋势、占比、排序、极值、阈值、身份**之一。它必须可真可假 | 说明、评论、口径声明、恒真句、建议 |
| **B 依据** | table 中决定 P 真值的**最小**格子集合，写成 (entity, x, field) 列表，并附算式 | 整张表；与 P 无关的格子；P 需要却没列进去的格子 |
| **E 证据** | 成片里"看到什么"才算讲到了 P。它是 G2 的输入，不参与 P 的真值判定 | 颜色、像素坐标、具体图元、原作者的箭头 |

一句话：**单元是一个可判真假的命题加它的最小依据，不是一个句子、一个数字、一个图表元素。**

由此推出四条操作约定：

1. **单元与句子不是一一对应。** 一句旁白可以同时表达两个单元；一个单元也可以由多句旁白加一张图共同表达。判定只看"这个命题有没有被成立地表达出来"。
2. **一个单元只计一次。** 近义句、重复念数、多个标注支持同一命题，都不加覆盖分。
3. **单元不含答案的时间位置。** 什么时候该出现属于 G3，不写进单元。
4. **限定词是 P 的一部分。** 人群、时间窗、单位、聚合口径（bar_34 的 "Americans"）写进单元内部，不另立单元，见 2.4.0。

**G1 的骨架是 intent 里的"槽"。** intent 每要求实现一件事（比较、变化、趋势、占比、极值、阈值、身份），就是一个槽；一个槽对应一条单元，条数由槽数决定，见 2.4.3。

#### 2.4.2 四条判定条件

复核一条候选单元时，先过下面四条。**C3 就是 2.4.0 的定义，是唯一的"必需性"判据；C1、C2 决定它是不是一个合格单元，C4 决定它和别的单元是否重复。**

| 条件 | 操作化问法 | 不满足时 |
|---|---|---|
| **C1 可判定且为真** | 只用本档公开输入，能否算出 P 的真值？它是否为真？ | 不是单元。"增长显著""差距很大""这是平均不是合计"都过不了 |
| **C2 非平凡** | 只允许看 B 里的**一个**观测，能不能说出 P？ | 不是单元。这是"复述一个格子"和"两个格子合起来才算"的分界 |
| **C3 有义务（删除测试）** | 把 P 从作品里删掉，只读过 intent 的观众会不会认为任务没完成？ | 真、有信息量、但删了 intent 仍成立 → optional_valid |
| **C4 独立** | 这条和已有单元是不是服务同一个槽？其中一条是否被另一条蕴含（同 B 或同组数据）？ | 同槽的强弱两种说法合并，留信息量大的那条；同 B 直接合并 |

三条判定细节，避免各人理解不同：

- **C2 的"两个观测"必须是不同行 / 不同实体 / 不同时点。** 同一行的两个字段不算两个观测。所以"份额 0.125，其补集是 0.875"只有一个观测，不是单元；"1990 年 20%，2019 年 7%"是两个观测，是单元。
- **C3 的两种过法，满足任一即可。** ①intent 的动词直接点名了这类信息（它说"比较"，就必须有比较单元）；②intent 的结论必须靠 P 才能成立（它问"谁更快"，就必须有跨实体的比较）。反过来，intent 里顺带提到的对象、年份、单位都不是单元——那是标签。
- **C4 先看槽，再看蕴含。** 同一个槽里的强弱两种说法算同一条（"七档单调上升"蕴含"两端点谁高"，留前者）；同一个事实的不同写法也算同一条：A 比 B 高 / B 比 A 低 / 差 260 / 是 B 的 1.29 倍 / 高 29%（同一对端点）；份额与补集；比值与反比；排序与支撑该排序的那几组两两比较；同一条趋势的"52 倍"与"最后一个月涨 7 倍"。**这些只能留一条**，写进同一条单元的 accepted_routes。

#### 2.4.3 标注程序：先把 intent 拆成槽，再填单元

1. **拆槽。** 读 intent，每个表示要求的动词或名词各算一个槽：比较 / 变化 / 趋势 / 占比 / 极值 / 阈值 / 身份。这一步决定 |G1|。
2. **填槽。** 每个槽到表里找最小 B，算出 P，并写下真值。
3. **过筛。** 用 C1–C4 逐条过；不满足 C1/C2/C4 的丢掉，只不满足 C3 的写成 optional_valid。
4. **写 E 和 reject。** reject 写"最容易被误当成满足本单元的那种说法"，供裁判用。

**单元数量是数出来的，不是规定出来的。** 一个槽只出一个单元；槽内允许多路证据（两端点、差值、比值都写进 accepted_routes），但**不能因为证据多就拆成多条单元**；intent 没有的槽也不要补。V1 的 50 条实测平均 1.76 条（88/50），旧稿按"3–5 条"写出来是 4.74 条，多出来的部分正是那 27% 的重复。intent 只要求一个判断时，1 条就是完整答案。

#### 2.4.4 明确不是单元的东西

| 类型 | 例子 | 卡在哪条 |
|---|---|---|
| 单格复述 | "2021 年的相对值是 0.125"；"份额 12.5%，其补集是 87.5%" | C2 |
| 元评论 | "这张表只有一行，得不出趋势"；"样本量太小" | C1（不是关于数据的命题） |
| 口径声明 | "单位是 percent"；"这是人均不是总额"；"取的是毕业时点" | C1 |
| 恒真句 | "数据覆盖 2015 到 2018 年"；"共有四个类别" | C2（读表即得） |
| 排版与渲染 | 颜色、图例位置、柱子宽度 | 不属 G1；V3/V4 的风格义务单列 |
| intent 提了但表里没有 | intent 讲"基础设施改善"，表里只有儿童死亡率 | C1（不可判定，记 unsupported） |

#### 2.4.5 正例

**例 1：协议自带的 A/B 增长。** intent 有三个要求："分别量化两者各自的变化"×2 + "用定量证据说明哪个增长更快"，所以是三个槽。

| 单元 | P | B | 为什么过 |
|---|---|---|---|
| U1 | A 从 100 增到 160，增 60（+60%） | a_2022, a_2023 | C3：intent 明确要求量化 A 的变化 |
| U2 | B 从 100 增到 120，增 20（+20%） | b_2022, b_2023 | 同上，换 B |
| U3 | A 的增长率是 B 的 3 倍（或高 40 个百分点） | 四行 | C3②：不给跨实体比较，"谁更快"无法成立；C4：B 与 U1/U2 不同 |

U3 的三条写法（3 倍 / 40 个百分点 / 两边都列出增长率）是同一条单元的 accepted_routes，不是三条单元。

**例 2：bar_27（七档收入 890 → 1150）。** intent 只要一件事：收入越高的家庭 SAT 平均分越高。所以 G1 只有 1 条。

- P：平均分随收入档**单调上升**，最低档 890、最高档 1150。
- B：七行全部——缺任何一档都无法宣称"单调"。
- accepted_routes：两端点 890/1150；高 260 分；高 29%（1.29 倍）；七档逐个列出。

"1150 比 890 高""差 260 分""1.29 倍"在这里是**同一个事实的不同写法**，按 C4 只留一条。

**例 3：line_82（医用氧气需求）。** intent 只要"需求暴涨"这一个判断。

- P：日需求从 2020-03 的 200,751 涨到 2021-03 的 10,501,155，约 52 倍；其中最后一个月从 1,500,578 涨到 10,501,155，约 7 倍。
- B：三个时点的行。
- 说明：全年 52 倍和最后一个月 7 倍是**同一条趋势的两路证据**，不拆成两条单元。

**例 4：area_16（埃塞俄比亚儿童死亡率）。**

- P：儿童死亡率从 1990 年 20% 降到 2019 年 7%，降 13 个百分点（相对 −65%）。
- B：1990、2019 两行。
- 说明：intent 还提到"基础设施改善"，表里没有对应列，**不是单元**，记 unsupported；不能因为原作者讲了就要求模型讲。

**例 5：donut_42（单行表）。** 表只有一行：11%，intent 就是这一条。

- P：养猫人群"更可能内向"的幅度是 11%。
- B：那一行。
- 说明：这是 C2 的例外——表里只有一个观测时，**这个观测本身就是唯一单元**。否则这条 clip 的完成度分母为 0，模型做什么都无从判定。同理适用于 340 条里全部 43 条单行表。

#### 2.4.6 反例（都是我们真实踩过的）

**反例 1：bar_144。** 表只有一行 `2021 = 0.125`，旧稿写了 5 条：

| 旧单元 | 为什么不成立 |
|---|---|
| "唯一实体是 2021" | 元评论，卡 C1 |
| "2021 的相对值是 0.1250，是唯一端点" | 单格复述，卡 C2 |
| "0.1250 小于其补集 0.8750，所以补集是多数" | 补集由同一格推出，只有一个观测，卡 C2 |
| "0.1250 相当于整体的八分之一" | 同一格的换算，卡 C2 + C4 |
| "只有一行，无法建立趋势或排序" | 元评论，卡 C1 |

按本节，这条 clip 的 G1 = 1 条（"2021 的份额约 12.5%"，端点型），其余全删。

**反例 2：area_37。** 表只有一行 `student debt = 30,000 usd`，旧稿 5 条里有 4 条是"这是人均不是总额""单位是美元""只有一个值所以不能排名""取的是毕业时点"。分别是口径声明、口径声明、元评论、口径声明，全部卡 C1，只剩"本科毕业时人均负债约 3 万美元"一条。

**反例 3：bar_27 的旧稿 5 条。**

- "图表展示的是收入档与 SAT 平均分的关系"——表头级说明，卡 C2。
- "最高档高于最低档：1150 vs 890" 与 "两者相差 260 分"——**同一对端点**，卡 C4，合并。
- "80,000 档是第一个超过 1000 分的档（994 / 1006）"——命题成立、B 也不同，但 intent 没要求阈值：删除测试通过，降为 optional_valid，不进 required。

**反例 4：intent 里没有的对象。** intent 只说"比较两个区域"，标注却要求"必须提到 2016 年的异常值"。这是把原作者的取舍偷渡成隐藏要求（见 2.2）。

#### 2.4.7 边界例（两个标注者最容易判得不一样的三类）

**一、清单式 intent 该拆几条——bar_71。** intent 用的是"breakdown by segment"，这是**一个构成槽**。四段各自的份额区间共用同一张表、同一句义务，按 C4 是同一条单元，写法是把四段份额列进同一条的 accepted_routes。旧稿给它写了 4 条"某段份额在多少之间"，就是把一个槽拆成四条。反过来，"线上商店每年都超过一半"成立、不与构成重复，但删掉后"讲清构成"依然成立，属 optional_valid。

**二、跨指标对比算不算一条——bar_109。** intent 有两个槽：①各收入组的初始接种差距；②加强针集中在高收入国家。required 是 2 条。"高收入国家加强针 16.1% vs 低收入国家全程接种 1.15%"这条跨指标对比 B 不同、命题也不同，但要不要算 required 取决于 C3：本条 intent 把两件事绑成一个判断（"在初始分配极不均的背景下质疑加强针优先级"），它可以作为第 2 条单元的 accepted_route；若 intent 只要求其中一件事，它降为 optional_valid。**判据是删除测试，不是"它看起来很有信息量"。**

**三、多路证据该不该拆——line_82。** 把"52 倍"和"7 倍"分别写成两条单元，B 不同、命题也不同，看着都能过 C4；但它们是同一个槽的两路证据。区分方法：**问这两条能不能被同一句话同时满足**——能，就是一条。

#### 2.4.7.1 G0 数据完整性、G1 `R1` 呈现单元与 G2 图元检查

“哪些 bar 必须出现”由 G0 的 `data_table.csv` 定义：通常取全部
`role=bar` 行，无 `role` 列时取全部数据行。**每条 bar 的第一个 requirement
固定为 `R1`，问题为“这个视频是怎么展现这些 bar 的？”**。`R1` 下按状态
组织完整性 U：

- 单状态图：一个 U，列出该状态的全部数据柱和堆叠段。
- `state_sequence` 图：每个声明状态各一个 U，全部 U 由 `R1` 以 `all_of`
  绑定。比如两个状态就是两个完整性 U。

G2 负责检查每个完整性 U 的 basis 中的标记是否真的出现在对应状态。缺失
任意状态中的任意数据标记时，该状态对应的完整性 U 为 0；其他语义单元仍按
各自的 C/V/T 记录。完整性 U 与其他 U 一样进入 G1 权重和固定分母。

- 普通柱、分组柱、堆叠柱都必须显示输入表中全部数据柱/堆叠段。
- 分组柱的每个“类别 × series”柱子都算一个必需数据标记。
- 堆叠柱的每个“类别 × series”堆叠段都算一个必需数据标记。
- Range bar 的两个端点都必须存在；不能只画上界或下界。
- `role=annotation` 的非柱事实不算数据柱，但若它本身是核心 G1 内容，仍按对应单元单独判定。
- 缺失任意一个必需数据柱或堆叠段时，该状态对应的完整性 U 为 0；
  其他语义单元仍按各自的 C/V/T 分别记录。
- 不允许用首尾两根柱代替中间柱，也不允许因某根柱数值很小、接近零线而省略。
- `time_behavior=frame` 的柱图不能只检查“整段视频里曾出现过”。G2 必须按
  G0 中的状态检查完整时间线：每个声明状态都要出现，且该状态下的全部柱或堆叠段
  都要齐全。任一状态的任一必需标记缺失或提前消失，该状态的完整性 U 为 0。
- 单柱变化图检查每帧应有的一根柱；多柱 bar race 检查每帧应有的一组柱；
  只截取末帧无法证明前面状态齐全。

统一记录格式：

```json
"g0_data_completeness": {
  "required": true,
  "mode": "static_all_at_once | state_sequence",
  "selection": "all bar-role data rows; all data rows when role is absent",
  "required_data_rows": 5,
  "required_states": ["1990", "2017"],
  "required_marks_per_state": {"1990": 4, "2017": 4},
  "evaluated_in": "G1_R1_completeness_units_and_G2_mark_presence",
  "g1_requirement_id": "R1",
  "g1_unit_ids": ["U1", "U2"],
  "check_full_timeline": true,
  "final_frame_only_sufficient": false,
  "missing_any_fails_visual_completeness": true
}
```

#### 2.4.8 记录格式与两人一致性

每条单元至少记：`unit_id / meaning(P) / unit_kind / basis(B) / computation / accepted_routes / reject / visual_evidence_rule(E) / required_candidate`。`required_candidate` 是标注者的判断，最终 required/optional 由复核者裁决，裁决结果写回同一条记录。

一致性检查：两名标注者独立拆槽、独立填单元，先比**槽数**，再比**单元对齐**（B 相同即对齐），只对有分歧的条目裁决。论文里报告槽数一致率与单元级一致率（Krippendorff's α 或 Cohen's κ），不要只写"两人讨论后一致"。

#### 2.4.9 这套定义在文献里的对应物

没有一个学科统称叫"必需语义单元"；这四个子问题各自都有成熟做法，我们的定义是它们的组合。

| 要解决的问题 | 文献里的对应概念 | 关键做法 | 我们的用法 |
|---|---|---|---|
| 单元切多细 | Pyramid 的 SCU（Summary Content Unit） | 单元是"最小意义单位"，人工把每句摘要映射到 SCU；SCU 权重 = 有多少标注者表达了它 | 粒度取"一个命题"；权重不用标注频率，改 1/n |
| 单元怎么验证 | FActScore 的 atomic fact | 把长文拆成"只含一条信息的短陈述"，逐条查是否有支持 | G0 负责判真，G1 只收 G0 判真的命题 |
| 义务从哪来 | CheckList 的 minimum functionality tests；data-to-text 的 content selection | 前者从任务规格推出"系统必须做到的行为"；后者把"该说哪些表记录"当内容选择，按记录算 recall | intent 拆槽 = 从规格推义务；表的记录 = 依据集合 |
| 语义和视觉怎么分开评 | Chart-to-Text / ChartMimic 一类图表基准 | 前者用数据表当事实基准；后者把"数据对不对"和"视觉像不像"分成两层打分 | 对应我们的 G1（语义）/ G2（视觉证据）分离 |

参考：

- Nenkova & Passonneau, *Evaluating Content Selection in Summarization: The Pyramid Method*, NAACL 2004（ACL Anthology `N04-1019`）；期刊版 Nenkova, Passonneau & McKeown, *The Pyramid Method*, ACM TSLP 2007, doi:10.1145/1233912.1233913。
- Min et al., *FActScore: Fine-grained Atomic Evaluation of Factual Precision in Long Form Text Generation*, EMNLP 2023, doi:10.18653/v1/2023.emnlp-main.741（arXiv:2305.14251）。
- Ribeiro et al., *Beyond Accuracy: Behavioral Testing of NLP Models with CheckList*, ACL 2020, doi:10.18653/v1/2020.acl-main.442。
- Wiseman, Shieber & Rush, *Challenges in Data-to-Document Generation*, EMNLP 2017, doi:10.18653/v1/d17-1239。
- Kantharaj et al., *Chart-to-Text: A Large-Scale Benchmark for Chart Summarization*, ACL 2022, doi:10.18653/v1/2022.acl-long.277。
- ChartMimic: *Evaluating LMM's Cross-Modal Reasoning Capability via Chart-to-Code Generation*, arXiv:2406.09961。

两处必须和文献区分开：

1. **那些工作评的是"给定文本/图，内容全不全"，我们评的是"给定 intent 生成视频，该讲的讲了没有"。** 所以必需性只能相对 intent 定义（2.4.0），不能照搬 SCU 的"标注者写了就算"。
2. **Pyramid 的权重来自标注频率，我们的权重是均分 1/n**（学长口径：权重不均不好打分）。标注频率只用来做事后分析"哪类单元容易被漏"，不参与计分。

## 3. 一个完整样本：从 table 到 ground truth

本例仅用于展示协议。样例 JSON 分为 example_public_task.json 和 example_private_gt.json，两者都可分享给你们开发；真实隐藏测试集不能将 private_gt 交给生成器。

### 3.1 公开数据与意图

| row_id | region | year | users_million |
|---|---|---|---|
| a_2022 | A | 2022 | 100 |
| a_2023 | A | 2023 | 160 |
| b_2022 | B | 2022 | 100 |
| b_2023 | B | 2023 | 120 |

单位：百万人。数据为构造示例，与真实地区无关。

公开 intent：

> 为普通观众制作约 30 秒的数据视频，比较 A、B 在 2022 到 2023 年的用户增长。分别量化两者各自的变化，并用定量证据说明哪个增长更快。仅基于提供的数据，不推测原因或未来走势。

示例工程设置为 1280×720、30 fps、允许 27–33 秒；这只是该演示任务公开的容差，不是已验证的普适标准。公开约束还明确要求有中文旁白和数据视觉证据，但允许图表标注补充未被念出的数值。

公开任务已要求两者变化与比较，但没有泄露答案 60%、20%、40 个百分点或 3 倍。

### 3.2 G0：事实目录与可执行依据

| fact_id | 命题或量 | 计算依据 | 结果 |
|---|---|---|---|
| a_start / a_end | A 两个年份的用户数 | 按 region/year 查询 | 100 / 160 百万人 |
| b_start / b_end | B 两个年份的用户数 | 按 region/year 查询 | 100 / 120 百万人 |
| delta_a / delta_b | 绝对增量 | end − start | 60 / 20 百万人 |
| rate_a / rate_b | 相对增长率 | (end − start) / start | 0.6 / 0.2，即 60% / 20% |
| rate_gap_pp | 增长率差 | 100 × (rate_a − rate_b) | 40 个百分点 |
| rate_ratio | 增长率比 | rate_a / rate_b | 3 |
| faster_a | A 增长更快 | rate_a > rate_b | true |

匹配单位与口径：60 百万人、6000 万人是等价表示；60% 与 0.6 只有在增长率语义下等价；“高 40%”不能自动当成“高 40 个百分点”；“增长到 160%”和“增长 60%”需要检查相对基准。定性“显著”如果暗示统计显著性，不能仅凭两个数值推出。

程序只执行受限计算表达式，不执行生成模型给出的任意 Python/SQL。对零分母、负基线、缺失值、四舍五入、加权平均和聚合粒度预先定义政策。

### 3.3 G1：三个必需语义单元（按 §2.4 判定）

| unit_id | 必需含义 | 接受条件 | 不接受 |
|---|---|---|---|
| U1 | A 的变化 | 实体与年份清楚；正确表达起终值、绝对增量或增长率之一，并建立变化含义 | 只报终值，不说明变化；只说“增长了”而无量化依据 |
| U2 | B 的变化 | 同 U1，针对 B | 只讲 A；把 B 的增长率说成 60% |
| U3 | 谁更快及其证据 | 明确 A 更快，并给出合法的跨区域定量比较；量化证据可在紧密关联的邻接场景中提供 | 只宣称 A 更快；比较不同口径；无依据解释原因 |

同一组画面可以同时支持多个 unit，不要求重复叙述。每个 unit 最多计一次，近义句和重复数字不能增加分数。

按 §2.4 的条件逐条核对：三个单元对应 intent 的三个槽（量化 A、量化 B、跨区域比较）。U1/U2 靠 C3①（intent 明写"分别量化两者各自的变化"）；U3 靠 C3②（不给跨实体比较，"谁更快"无法成立）。U1 的"起终值 / 增量 / 增长率"是 accepted_routes，"3 倍 / 40 个百分点 / 并列增长率"同样是 U3 的 accepted_routes，都不是额外的单元。

U1/U2 可由旁白或清晰的图形标注传达；U3 必须明确表达比较结论，可以在旁白或可读的结论标注中出现。最终作品不能有相互矛盾的表述。是否要求某个信息必须被念出来，应由公开任务指定，不能隐藏加分。

### 3.4 G2：视觉证据不是固定图形

U1/U2 的有效视觉证据可以是起终值并列柱、折线端点、编码正确的变化标注，或清楚展示变化量的图形。必须可辨认实体、统计量和时间范围，必要的单位/图例应可用。

U3 的有效视觉证据包括：

- 两区域增长率并列展示，使用共同且标明的尺度；
- 两组起终值同时展示，能清楚建立各自变化及跨区域关系；
- 跨镜头比较，但前一对象的关键信息在比较发生时仍能通过保留标注/摘要等方式获得；
- 其他经人工核验能支持同一比较的视觉表达。

只把“A 增长更快”写成字幕，不算完成 U3 的数据视觉化。旁白字幕可帮助理解，但不替代数据图形证据。数据卡、数值比较板可以是合法形式，前提是用布局/关系清楚组织数据，而非逐句字幕化；不应机械要求必须画柱子。

GT 记录可接受证据条件，不固定颜色、像素坐标、SVG 元素 ID、路径数量或原作者使用的箭头。

### 3.5 G3：时间规范绑定生成旁白

若生成旁白在第 8–11 秒讲 A 的变化，U1 的视觉证据应在该语境下充分可见；若另一个系统在第 3–6 秒讲同一内容，则用它自己的时间窗检查。

标注类型：

- availability：比较发生时，相关对象和必要信息可获得。
- ordering：在解释依赖关系需要时，先建立对象再比较；不是所有叙事都强制先 A 后 B。
- identity：跨帧颜色、位置或标注变化不应造成实体混淆。
- dwell：证据出现时间足够读懂；不要求逐字同步。
- transition：入场动画的中间几何状态不得被当成已完成的数据状态逐帧判错；但若旁白已经断言完成值而长时间未显示，应在对齐/表达中体现。

不预设 0.5 秒是普适阈值。开发集通过提前、延迟、缩短停留等实验校准容差，并冻结政策。报告连续时间误差与阈值敏感性，不只给一个 pass/fail。

## 4. 如何从你们现有素材建立 GT

### 4.1 数据一致性核查

逐条对齐原始 table、原 narration 和原视频：确认单位、时间范围、聚合方式、样本量口径一致。对冲突单独记录。

- 确有可信原始数据：以核验后的数据为准，不能为了参考视频改错真值。
- 只有从图表反推的数据：标记 reconstructed，记录不确定性和精度；不得与真实原始数据无区别混用。
- 参考视频表述错误：修正标注、重写 intent 或排除样本，不能把错误当成 GT。
- 难以核实的样本不进入硬事实评测核心集，可作为探索性子集单独报告。

### 4.2 从参考中抽取候选，再独立于参考复核

1. 抽取参考 narration 的 atomic claims、实体、数据操作和时间段。
2. 从参考 SVG 定位 marks、labels、axes、legends、annotations 与对应数据。
3. 根据参考故事提出一个用户自然会发出的 intent，去掉答案泄露。
4. 让另一位标注员只看 table、schema、intent，列出合理的必需内容与多种表达方式。
5. 对比两份标注：无法从输入推出的“参考特有内容”降为 optional，不计入 required。
6. 用脚本计算事实目录并测试接受条件。

反向构建 intent 容易把原作者的选择固化为唯一答案。第 4 步是关键控制；明确 intent 的生成流程，并保留 source-derived / independently-authored 标签。

### 4.3 SVG 需要补什么，不需要补什么

建议标注：元素角色、实体/字段/时间绑定、相对比例/关系、跨帧身份、参考事件窗口、抽取置信度。

无需为每一个装饰性 path 标完整语义。优先覆盖与 required units 有关的数据图元、轴、标签和强调动作。

只有关键帧 SVG 时，不能假定已经拥有动画时序 GT。仍需回看视频标事件；无法获取的时序信息保留 missing，不能由帧序推造精确秒数。参考窗口只是理解素材的辅助，不用于要求新视频复刻。

### 4.4 双人标注和裁决

核心测试样本由两人独立标注 required units 与证据条件，再裁决分歧。有限人力可先只做精标核心集，外围样本单人初标加抽检，并分别报告覆盖。

记录 disagreement types：统计口径、是否必需、等价表达、视觉证据不足、时间窗歧义。对没有唯一合理答案的样本修改公开任务或移入开放子集，不通过增加隐藏规则强行消除分歧。

## 5. 提交代码与执行 harness

### 5.1 建议的最小 API

以下是待实现的接口设计，不表示当前已有 SDK：

```javascript
window.benchmark = {
  ready: async () => { /* Load only declared local assets. */ },
  renderAt: async (timeSeconds) => { /* Render the exact state at this time. */ },
  getDuration: () => 30
};
```

renderAt 允许任意顺序查询 t，不能仅把实时动画暂停后冒充可重复 seek。系统可自由编写图表、数据变换和动画；接口只统一时钟和采集，不负责替模型生成内容。

若支持原生实时 D3 transitions，应由适配器统一时钟并核验录屏与采样状态一致，不能假设异步计时器天然可重复。先定义 seekable 模式，可显著降低复现难度；限制需要在论文中写清。

### 5.2 同一次执行采集

- 固定画幅、设备缩放、字体、浏览器、依赖版本和资源来源。
- 以正式视频帧率渲染；采样检查采用均匀基础采样 + narration 边界 + 事件变化附近加密。
- 同时保存该时刻截图与 DOM/SVG 快照、computed style、变换矩阵、几何边界、运行错误。
- 最终视频由同一时间轴的渲染帧和官方音频合成，检查时长和音轨。
- 全部可见文本、图例与数据图元是评测对象。少量采样不能声称证明全视频无错，应报告采样策略及短暂事件漏检率。

元素有 DOM 节点不等于可见。display/visibility、opacity、变换、裁剪、遮罩、视口和层叠遮挡都可能影响实际呈现。结构检查生成可疑项，截图/人工验证真实遮挡。浏览器几何 API 不能自动解决全部可见性与语义问题。

### 5.3 隔离和信息边界

执行不可信代码须隔离网络与文件系统、禁用任意进程调用、设资源/时间上限、固定允许依赖。隐藏 GT 不进入浏览器目录、提示词、控制台或可请求接口；生成器只可见公开反馈，如执行错误和自己的渲染预览。

禁止用模型自报的 hidden-pass 标记作为证据。评测模型也将候选代码、字幕和注释视为待评数据，不遵循其中任何要求改分或忽略规则的指令。

本阶段不执行真实用户提交代码；这里只设计协议。

## 6. 程序、LLM、VLM 和人工如何协同

### 6.1 旁白：先观察，再查表

- 将最终音频与提交文本对齐，核对音轨真正说出的内容。
- LLM 抽取去重 atomic claims，保留原句、时间窗、实体、时间范围、单位、操作、限定词。
- 程序根据受限事实表达式和输入表验证，不能把查找最近数字当作验证。
- 评测端独立审核 claim→query 映射；程序算对了错误查询仍然是错评。
- 新的合法派生事实动态求值；不因未出现在预定义 fact catalog 就判错。

标签至少包含 supported、contradicted、unsupported、unresolved。unsupported 是证据无法支持；unresolved 是评测器无法确定，两者不能混淆。nonfactual 修辞另标，不混进 factual precision。

### 6.2 图形：结构辅助，但不信任自报语义

优先支持少量典型编码，如标准柱状图、折线、比例图和数据比较卡。对每类编码说明结构提取覆盖和边界。

核验链为：元素定位 → 实体/字段/时间对应 → 比例尺/单位 → 实际几何与可读标签 → 截图可见性。data-value、D3 绑定对象、代码中的数组只能支持其中一部分。

例：对于共用线性零基线的两根柱，可用高度和比例尺核验数值；但截断轴、log 轴、堆叠柱、面积编码不能套用同一高度比例公式。程序必须先识别编码类型及其前提。不知道前提时应转交视觉/人工，不应武断打错。

### 6.3 视觉模型：提取与判断分开

推荐两阶段：

1. 观察阶段：输入相关连续帧/短片、需观察的实体与字段，不提供标准答案数值。独立提取图形中的值、关系、标注和位置，允许 unknown。
2. 核验阶段：将观察与 table、GT 单元比较。表达质量评判可看完整 intent 和实际音轨，但须引用时间/区域证据。

不能仅凭字幕回答 chart-fact QA。图形事实通道屏蔽旁白字幕或明确要求引用非字幕数据图元；保留图表自身的数值标签、轴与图例。遮字幕也不能遮掉必要图形信息，裁剪/遮罩应被验证。

对读不清的小数值，不让 VLM 猜一个接近答案的数字。使用 unknown，并进入人工复核或分数区间。把一张图的整套正确数据给 VLM 再问“是否正确”，容易产生答案依赖，应避免作为唯一事实核验。

### 6.4 时间对齐

先匹配生成作品中各单元的所有语义表达位置，再确定语境窗，最后检查正确证据、身份与可读性。口述内容以生成音频为锚点；未被口述但合法通过图形/结论标注表达的单元，以可读语义标注和场景上下文为锚点，不因没有口述窗口而判失败或剔除。

重复出现的同一单元：先合并同一连续说明过程，再检查所有语义匹配到的出现位置，不允许事后只挑最有利片段。二元 T_u 通过要求所有实际承担该信息表达的出现均无实质错配；另报 occurrence-level 对齐比例用于诊断。泛指背景提及不算新的完整表达，匹配政策在开发集冻结。若重复次数很多，该严格策略的影响需分层报告。

结构轨迹用于测某个对象何时出现/改变，VLM/人工用于判定变化是否真正支持所讲内容。

不强制每次提到实体都高亮，也不奖励高亮所有对象。全程静态但清楚、可比较的图形可能在某些单元上完全有效；只有任务确实需要时序揭示、动态过程或连续比较时，才明确要求相应变化。动画有效性另评，不以帧差幅度替代。

图和旁白一致但共同错误时，同步诊断可通过，事实指标失败；主端到端指标必须同时要求真实性，防止两者互相“作证”。

### 6.5 人工证据集与裁判提示

人工评价的对象是生成作品而非模型名称；随机顺序、可判平局，至少由两名评审对校准子集独立判断。开发和最终测试裁判校准样本隔离。

每个自动判断返回：unit/claim ID、label、evidence timestamps、区域/元素证据、理由、是否需复核。不要只让裁判输出一个总分。可读性/叙事评分用完整锚点，不能把“画面精美”作为事实正确的证据。

### 6.6 三个可直接改写为提示词的裁判任务

**旁白提取器**：只提取实际音轨/转写中的可核验陈述；每条保留原文、时间段、实体、统计量、单位、时间范围、比较对象和限定词。不要补充模型没有说出的内容，不要先看正确答案后补全。输出 claims 和无法确定的片段，不直接给总分。

**图形观察器**：你会收到连续帧/短片及需要定位的实体与字段。请报告实际看见的图元、轴/图例、数值和关系，附时间与位置。旁白字幕不是图形事实证据；不得根据题意猜数值。不可读、遮挡或无法建立绑定时输出 unknown，并指出原因。

**单元裁判**：依据公开任务、单元接受条件、已核验的事实与观察证据，分别判断 C/V/T。新表达只要满足同一语义条件可以通过；不得因不同于参考布局扣分。证据冲突时记录冲突，不使用多数投票掩盖。输出标签、证据引用、理由与需复核标记。

裁判可以使用不同模型或同一模型的分阶段调用，但分阶段本身不保证独立或无偏。将候选系统身份和自报得分隐藏，固定裁判版本/参数，保留重复评分的一致性测量。

### 6.7 每个候选作品需要保存的评分证据

建议 result record 至少包含：sample_id、system/run_id、input/code/audio hashes、runtime version、生成与基础设施状态、每条 claim 的原句/时间/查询/标签、每个视觉 assertion 的位置/编码前提/标签、每个 unit 的 C/V/T 与证据窗口、人工裁决记录、聚合分数与各列分母。

这份输出侧记录不是预先 GT，而是该作品被评分的审计轨迹。遇到新合法表达时，只扩展等价表达实现或更正评测器，不能改原任务义务；变更版本并对所有受影响系统重新评分。模型自报 evidence_map 与裁判确认的 evidence record 必须分开存储。

## 7. 指标定义与分母政策

主质量画像使用任务完成、旁白事实、视觉事实、时序表达及人评呈现。以下为建议定义，阈值需在开发集校准后冻结。

### 7.1 固定分母的任务指标

对样本 i，预标注 required units 集合 R_i。每个 unit 有固定权重 w_u，首版默认等权；权重只在看到输出前确定。

定义四个独立判断：

- C_u：所需信息在最终作品中被正确且明确传达，字幕/旁白/图表标注可按该单元公开通道要求满足；若作品中存在与该核心结论冲突的陈述，不能算通过。
- V_u：实际可见图形独立提供正确、可辨认的数据证据，不仅是旁白字幕。
- T_u：证据与生成叙事的语境对齐，并满足必要顺序、停留与身份条件。
- A_u：该单元是否要求视觉证据，来自预标注。主集建议所有 required units 都是数据视觉叙事单元，即 A_u=1。

```
ContentCompletion_i = sum(w_u * C_u) / sum(w_u)
VisualCompletion_i  = sum(w_u * V_u for A_u=1) / sum(w_u for A_u=1)
JointCompletion_i   = sum(w_u * C_u * V_u * T_u for A_u=1) / sum(w_u for A_u=1)
```

如果未来纳入非视觉背景说明，单独报告其内容完成度，不强行把它们放进视觉分母。参考中没有、但语义等价的表达照样可以满足 C/V/T。

为定位“没画”与“画了但没对时”，另报条件对齐：只在 C_u=V_u=1 的单元上统计 T_u，并同时报可评价单元数。该条件分只能诊断，不能代替固定分母的 JointCompletion。

### 7.2 事实正确性：覆盖实际输出，包括额外内容

对去重后的 narration factual claims 集合 N_i、visual factual assertions 集合 F_i 分别核验 supported / contradicted / unsupported / unresolved。visual assertions 包括可见数值、类别绑定、趋势、排序和明确结论，不限于 required units。

```
NarrationFactualPrecision_i = supported(N_i) / size(N_i)
VisualFactualPrecision_i    = supported(F_i) / size(F_i)
```

上述点估计仅在全部 claims 已裁决时使用。重复同一正确数字不能重复加分；语义原子化要固定，避免模型把一句话拆很多次影响分母。补充报告每视频事实错误数和 AnyCriticalError：是否存在改变核心结论、实体或关键数量级的错误，由预先定义的严重性规则判定。

没有 factual claim 的作品，precision=NA，不能记 1；其必需单元完成度仍可能为 0。不用省略内容来换取完美事实分。

长而密集的图表可能有大量事实。核心集尽量全检；必须抽样时，公开抽样规则、抽样权重与覆盖率，命名为 audited factual precision，不能伪称已检验所有数据。不能只审 required facts 而放过额外编造。

### 7.3 不确定与执行失败

- unresolved 表示评测器不确定，不应直接算模型错，也不能从分母剔除后算高分。
- 对固定单元分数，令未裁决项取 0 得下界、取 1 得上界；对事实 precision，同样用 supported/n 与 (supported+unresolved)/n 给区间。
- 最终核心榜建议人工解决关键 unresolved 后再给点分；未解决的发布区间与覆盖率，不给虚假的精确排名。
- 输出缺失、代码失败、音轨缺失等任务失败，RenderSuccess=0，固定分母完成度=0。
- 已生成 narration 的局部事实分可作为条件诊断，但不可让失败系统凭局部文本获得整体完成分。
- 评测基础设施失败与模型失败分开：前者重跑/标 unavailable，不归零惩罚模型。
- 轻微时长偏差按公开容差处理；越界不悄悄截断视频再评分。展示约束符合率，并预先定义哪些违规为无效提交。

### 7.4 呈现质量与效率

人评或校准裁判采用三个 1–5 维度：

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| Narrative clarity | 缺乏可理解的比较/结论 | 基本连贯，有明显跳跃或冗余 | 结构清楚，信息选择与 intent 一致 |
| Visual readability | 关键信息不可读/不可辨 | 多数可读，有局部遮挡或短暂不足 | 关键信息清楚，单位/图例/阅读时间充分 |
| Animation effectiveness | 动画干扰或关键过程无法表达 | 支持部分表达，也有无效动作 | 动态变化或有意停留有效支持理解，无无关炫技 |

没有必要动画的样本不因静止自动扣分，也不因全静态自动高分；判断依据是是否服务于明确的表达需求。审美可做附加偏好，不纳入数据事实分。

效率报告总调用/token、墙钟耗时、渲染时间、TTS 次数与重试。金额需使用运行时已核验价格；本方案不预填成本结果。

### 7.5 汇总

主表建议列：RenderSuccess、ContentCompletion、VisualCompletion、JointCompletion、旁白事实 precision、视觉事实 precision、AnyCriticalError、三个人评维度、成本/延迟、Unresolved/Coverage。

逐列明确汇总集合：

| 列 | 纳入集合与缺失政策 |
|---|---|
| RenderSuccess、固定分母完成度 | 纳入全部有效评测尝试，模型生成失败记零；基础设施失败先重跑，仍不可用则标缺失并报数量 |
| 旁白/视觉事实 precision | 非空且可检查该模态的作品上条件汇总，并同时报 n/N；空 claims 为 NA，失败作品不靠局部文本进入整体榜 |
| AnyCriticalError | 在已检查作品上报错误率及覆盖；不能把未生成或未检查作品当作无错 |
| 条件对齐、人评质量 | 明确成功/可评价集合及数量，不将其说成全部任务成功率 |
| unresolved | 逐样本保留上下界，再分别汇总上下界；不取中点，不悄悄删样本 |

按视频先算再宏平均，防止长视频因句子多支配主结果。事实微平均可作补充。共享来源视频/数据表的样本在 bootstrap 中按来源组聚类；比较系统使用配对置信区间。系统间基础设施缺失优先补跑；不能补跑时，在共同可用样本上给配对比较，同时完整报告各系统覆盖和缺失分布，不把该比较冒充完整测试集结果。模型多次生成的不确定性与样本差异分开，报告实际次数。

不要把不同量纲直接等权平均。JointCompletion 是明确定义的任务完成率，不声称覆盖一切质量；任何综合排序都必须同时公开事实错误和资源成本。没有用户或社区确认的权重，不应伪装成唯一客观总分。

## 8. 示例评分：解释指标为何需要并存

本节为人为构造的离散情形，不是实测结果。为了说明，令 U1/U2/U3 等权。

| 输出情形 | 内容完成 | 视觉完成 | 联合完成 | 解释 |
|---|---|---|---|---|
| 只正确讲 A，也只画 A | 1/3 | 1/3 | 1/3（假设对时） | 事实可全对，但没有完成任务 |
| 旁白三项讲对，但唯一图表清楚地把 A/B 数值对调，否定全部三项 | 0/3 | 0/3 | 0/3 | 旁白局部事实可正确，但最终作品跨通道冲突；若绑定尚无法确定则标 unresolved，不直接给满分或零分 |
| 内容与图形都正确，但比较证据在比较结束后才显示 | 3/3 | 3/3 | U3 不通过 | 有内容不等于及时表达 |
| 正确完成三项，但额外声称增长由广告造成 | 3/3（未与核心比较冲突） | 3/3 | 可为 3/3 | 额外 unsupported claim 由事实指标和错误标记反映 |
| 与参考配色、布局完全不同，但正确清楚 | 3/3 | 3/3 | 3/3 | 不因自由设计扣分 |

这也是不宜只选一个主分数的原因：完成必需任务与不增加额外错误，是两个不同目标。

## 9. 证明评测器有效，而不只是能运行

### 9.1 两类验证数据都要有

- 受控变体：从经核验的参考或生成实现中一次只改变一个因素，建立可诊断错误。
- 自然输出：覆盖不同模型、代码风格、图表形式和真实错误，检验受控样本之外是否仍可靠。

只做受控变体会高估评测器能力；只做人评相关性又难以证明它能抓住小但关键的错误。

### 9.2 受控变体与预期反应

| 操作 | 应影响 | 不应被误伤 |
|---|---|---|
| 单个关键数值改错 | 事实正确、相应完成单元 | 不自动惩罚无关画面美感 |
| 交换实体标签 | 实体绑定、相关视觉事实 | 不因纯代码改名判错 |
| 删除比较证据 | 视觉/联合完成 | 仍正确的旁白事实 |
| 延迟证据或过早消失 | 时序/联合完成 | 静态数值是否正确 |
| 改变不影响识别的配色/字体/布局 | 语义分应保持 | 不要求像参考 |
| 用另一种合法图表表达相同关系 | 语义分应保持 | 不要求图元数相同 |
| 加一条无依据因果论断 | 额外事实错误 | 已完成的合法单元 |
| 加重复正确陈述 | 不增加覆盖或事实样本权重 | 不因重复数量刷分 |
| 隐藏正确数据图元、只留自报 metadata | 视觉完成应下降 | 不能信任 evidence_map |

改变字体/布局只有在仍可读、无新增遮挡时才是语义保持扰动。每个变体需要人工确认实际只改变预期因素。

### 9.3 校准与冻结

在开发集校准事实抽取、时间容差、可读时间及裁判提示。使用独立 held-out 自然输出与变体作最终验证，不可反复据测试错误调指标后仍称其独立验证。

报告：claim extraction precision/recall、claim→query 映射正确率、错误检测 precision/recall、等价变化误报率、时间偏移检测、自动分与人工分相关性/排序一致性，以及人工间一致性。语义 extraction 漏掉的错误也计入评测器失误，不能只看已抽出 claims 的准确率。

各类能力阈值需在试验后设定。本方案不预设任意“达到某相关性即可发表”的承诺。若自动评测尚不可靠，核心榜用人工裁决，自动结果标 provisional，并报告人工工作量。

## 10. 数据划分、污染与版权

按原始视频、数据表及近重复故事分组划分，不把同源片段或扰动变体分到 train/dev/test。模板近重复、同一配色并不足以判定内容泄漏，但共享事实与叙事结构需要重点检查。

建议维护：

- public development：公开数据、任务、GT 和少量完整评分示例，供调试。
- hidden test：生成器仅获输入；GT 和人工裁决不暴露。公开通用评分政策与标注规范。
- evaluator validation：用于验证裁判的独立作品/受控变体，与调提示样本隔离。

参考视频或 SVG 公开后，隐藏测试答案可能更容易被识别。不能声称隐藏就等于无污染；报告来源是否公开、是否可能出现在训练语料，并辅以新写 intent、新数据或可核验事实变体的独立子集。

原视频、配音、字幕和 SVG 的再分发应检查许可。抽取为 SVG 不自动消除原素材版权；不明确时发布链接/时间戳与自有标注，不直接打包受限媒体。

## 11. 基线与实验设计

建议最小比较：

1. 单次 coding 生成：同一公开输入直接生成代码与 narration。
2. 可运行自检 Agent：允许看自己的执行错误和视频再修复，预算固定，不能访问隐藏评分器。
3. 简单数据忠实基线：有限图表类型、规则计算事实、模板旁白与逐项强调，作为低设计自由度参照，不冒充任何已有论文方法的完整实现。
4. 经人工核验的参考实现：作为可行性与评测器 sanity check，不默认满分，也不是所有指标的绝对上界。

在同一模型上比较单次与 Agent 可看重试作用；不同模型之间同时报告预算。不要在没有官方代码和匹配配置的情况下把自建近似实现命名为某个已发表系统。

能力分层优先按任务负担：数值/比较/趋势/排序/占比、单图与跨图、叙事单元数、数据规模、视频时长。首版不要为了凑图表类别扩大到无法可靠评估的所有可视化。

## 12. 最小实施路线与验收

### 阶段 A：先把标注做对

选 20–30 个覆盖主要能力的样本试做，不将其当成发表规模承诺。每条完成：公开 intent、表口径、按 §2.4 拆出的必需单元（条数=槽数，不预设）、事实计算、视觉证据条件、歧义记录。

验收：独立标注员只看输入能理解同一任务义务；不同合理视频能被接受；参考错误不进入 GT。样本难度不由 required units 数量单独决定。

### 阶段 B：跑通 coding 与证据采集

实现统一时钟、音频、视频采集和两三类典型编码的结构检查。先人工完成评分，以确认每项判据确实可执行。

验收：能重现同一输出；DOM/截图/音轨时间一致；成功与基础设施失败可区分；不读源码注释就能判断最终结果。

### 阶段 C：自动评测器校准

在自然输出与受控变体上测量程序提取和 VLM 判断错误，建立 unknown/复核通道。自动评分不可靠的维度保留人评，不为了全自动而降低科学有效性。

验收：明确哪些指标可靠、哪些类型覆盖不足、哪些仍需人评；阈值和提示冻结，留独立验证集。

### 阶段 D：扩量并比较系统

按来源、任务能力与时长扩展，确定评测预算和人工抽检策略。发布主分项、错误类型、置信区间、失败与不确定比例。再根据必要性增加图表类型/运行时，不按预设月份承诺“旗舰级”。

## 13. 与旧 metric 清单的对应处理

- L1 保留 schema、执行与绑定诊断；删除数值集合命中作为 fidelity 的定义。
- L2 在本 table+intent 任务中保留；用 claim 核验 + required-unit 完成替代旁白相似度主评测，不奖励无证据因果和预测。
- L3 保留实际渲染、可读性与视觉事实；静帧率、图元重叠、运动幅度只作辅助信号。
- L4 升级为以生成音频为基准的视觉证据与时序核验；相同错误不能相互作证。
- L5 保留明确的叙事、可读性与动画有效性评分。理解度实验可选，需 audio-only 对照，避免旁白本身解释全部答题表现。
- L6 保留资源/失败/预算信息；事实改变的扰动必须同步更新 GT，不能要求结果不变。
- L7 电影化风格只作可选风格任务或分层分析，不进入主正确性评价。
- 删除未验证的等权复合分、无依据样本比例与“几周即可发表”的承诺。

## 14. 实现时必须明确的边界

1. **任务义务能否从输入推出？** 不能把参考视频的所有细节偷偷当标准答案。
2. **程序真的理解图形吗？** 任意 SVG paths、Canvas 与混合编码不能保证精确自动还原，需要覆盖声明和 fallback。
3. **GT 能否判新答案？** 参考 fact catalog 不是封闭世界，新的合理事实必须能查询验证。
4. **评测器是否只看到了答案？** 字幕、源数据、自报 metadata 不能替代实际图形证据。
5. **是否混淆生成失败与评测失败？** unresolved/infra failure 必须独立记录。
6. **是否把标准化变成了替模型做任务？** 统一时钟与音色可以，预置完整可视化答案不可以。
7. **是否只有参考而没有生成结果标注？** 自动评测器的有效性必须用真实候选作品验证。

## 15. 已核验的相关工作与证据边界

本节沿用本次讨论已查阅的原文信息，目的仅是解释设计来源，不构成完整 related-work/新颖性审查。

- [DATAREEL, arXiv:2604.25220v2](https://arxiv.org/html/2604.25220v2)：输入数据、传播意图、时长和风格参考，代码生成后渲染；已有 HTML 评判及视频级字幕—动画一致性评价。不能把“完全没有跨模态评测”作为差异化。本文建议强化可执行事实与单元级证据核验。
- [DataMagic, arXiv:2606.20388v1](https://arxiv.org/html/2606.20388v1)：DVSpec 数据绑定、叙事索引触发；评估含执行率及五维质量自动评分与人工校准。数据引用机制不等于“数值出现在原表即可证明正确”。
- [VBench, arXiv:2311.17982](https://arxiv.org/html/2311.17982)：细分视频质量维度；通用一致性和运动代理不能不加验证地迁移为数据视频正确性标准。
- [VideoAgent / SciVidEval, arXiv:2509.11253v2](https://arxiv.org/html/2509.11253v2)：科学视频多模态评测和观众问答可作参考，但本任务需额外验证数据事实、图形编码及开放叙事选择。

## 16. 交付文件与当前未实现项

- evaluation_protocol.md：本方案的可编辑正文。
- evaluation_protocol.html：同一正文生成的阅读版，不是另一套协议。
- example_public_task.json：一个完整的公开输入样例。
- example_private_gt.json：对应的评测端 GT 示例，包含事实表达式、必需单元及证据条件。
- validate_example.py：只校验样例数据、事实计算和引用完整性；不是视频评分器，也不证明指标有效。
- build_reading.py：由 Markdown 重建阅读版的辅助脚本，需要 Python-Markdown；样例校验本身只需 Python 标准库。
- data_video_evaluation_bundle.zip：打包上述六个文件，便于交给合作者。

运行 `python3 validate_example.py` 可核对构造样例的 11 个事实、3 个必需单元、引用关系、公开/评测字段隔离及联合分数例子。校验通过只说明这些样例自洽，不表示自动裁判已经验证。

当前尚未实现：浏览器执行 harness、D3/SVG 语义解析器、TTS 对齐、自动 claim 抽取、VLM 裁判、人工标注平台。时间容差、视觉数值容差、自动裁判可靠性均需开发集验证。JSON 为数据契约示例，不是已部署 API。

最关键的结论：**你们需要交付的是“输入支持什么、任务要求什么、画面需证明什么、何时需证明”的 GT 包，而不是一条唯一标准视频。coding 限定让证据更容易采集，但不会自动消除语义与时序判断的难点。**
