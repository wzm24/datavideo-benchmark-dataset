# Intent 与 G1 的质量评估方案

版本：2026-10-20  
定位：评估"我们自己的 GT"是否可靠，不评模型输出。与 `evaluation_protocol.md` §2.4（G1 定义）、
§2.5（intent 三层）配套使用。本文是方案，不是实验结果。

## 0. 总览

两层、三种手段：

- **两层**：intent（任务要求）和 G1（要求的接受条件）。
- **三种手段**：机器闸（全量）、往返检查（模型 + 抽检）、人工验收（抽样）。

顺序固定：**先评 intent，再评 G1**。intent 不合格，G1 不进入正式评测集。

## 1. Intent 的质量评估

intent 指"叙事目标 + 任务要求"合成的一句话。评它有没有把任务说清、有没有泄露、能不能推出 G1。

| 维度 | 具体指标 | 谁算 | 判定方式 |
|---|---|---|---|
| 形式 | 一句话、≤32 词、祈使句、无 clip_id | 机器 | 正则 + 分句计数 |
| 不泄露 | 数字泄露率（年份除外）、方向词/结论词率 | 机器 | 正则 + 人工抽检误报 |
| 范围 | 实体/时间/指标/口径能在表里查到的比例 | 机器 | 实体匹配 + 表头检查 |
| 要求覆盖 | requirements 被这句话覆盖的比例 | 模型 + 抽检 | all_covered / partial / missing |
| 内容往返 | 只看 intent + 表能否复现原片主干 | 模型 + 抽检 | closed / partial / open / off_table |
| 稳定性 | 同一 intent 跑两次，要求数是否一致 | 机器 | 两次运行的 requirements 数 |
| 人工验收 | 五条验收（见下） | 人 | pass / revise / drop |

五条人工验收：

1. 任务是否清楚：实体、时间、指标、口径是否明确。
2. 所要求的结论是否能由给定数据回答。
3. 每项 G1 是否都能从公开要求推出。
4. 不同但合理的叙事方案是否都能通过。
5. 是否在任务里提前给出了本应由模型分析得到的答案。

**往返测试**：把 intent 藏起来，让另一个 agent 只看 intent + 表推出它会讲什么，再与原片主干比对。
闭合 = 这句话承载了任务；不闭合 = 写漏或写糊；`off_table` = 原片讲了但表里没有，单独成桶，
不算 intent 写错。

最终结论三选一：`pass / revise / drop`，外加 `off_table` 标签。

### 1.1 与原片主干比对：三步流程

主干不是旁白全文，也不是所有句子。主干是**论题级主张**：删掉它，这条片子就没有观点了。
一般 1–3 条。三个角色必须独立，避免循环论证。

#### 第一步：建主干（不看 intent）

一个独立 agent 或人只看 **原片旁白 + 关键帧/SVG + 表**，输出：

```json
{"main_claims":[
  {"id":"M1","claim":"无保险美国人因费用跳过服药的比例最高","level":"thesis","in_table":true},
  {"id":"M2","claim":"有保险美国人排第二，且高于所有非美国国家","level":"thesis","in_table":true},
  {"id":"M3","claim":"这反映了政策优先级问题","level":"aside","in_table":false}
]}
```

- `level=thesis` 才算主干；`support` 是论据，`aside` 是顺带说的一句。
- `in_table=false` 的不参与比对，进 `off_table` 桶。
- 写不出"删了它观点就没了"的，不算主干。

#### 第二步：独立复述（盲测）

另一个 agent 只看 **intent + 表 + chart_spec**，不看旁白，输出"一个正确的视频会讲什么"：

```json
{"claims":[
  {"claim":"无保险美国人 33.5%，最高","entity":"uninsured US","relation":"highest"},
  {"claim":"有保险美国人 20.1%，第二","entity":"insured US","relation":"second"}
]}
```

要求它**算**，不是复述任务：任务是比较，就必须说出谁高谁低、差多少。

#### 第三步：结构化对齐

把两边 claim 规整成 `(实体, 指标, 时间窗, 关系, 数量级)`，按实体+指标+时间窗配对，再比关系：

| 情况 | 判定 |
|---|---|
| 实体、指标、关系、数量级都对上 | covered |
| 主体对，但缺一个必需部分（时间窗、对比集合） | partial |
| 方向/排序/数量级相反 | **contradicted** |
| 主干里根本没有 | missing |

数值比较用方向和量级，不用精确相等：0.6 与 60% 归一化后等价；±5% 内算同一数量级；排序必须一致。

#### 判定规则

- `closed`：所有 thesis 主干都 covered，且没有 contradicted。
- `partial`：有 missing 或 partial，但没有 contradicted。
- `open`：出现 contradicted（说反了比漏说更糟），或主干完全没复现。
- `off_table`：主干里没有一条 `in_table=true`。

分数：`coverage = covered / 主干条数`，另报 `contradiction count`。

#### 两个例子

**bar_34**：主干 M1 无保险最高、M2 有保险第二且高于所有非美国家。
复述给出 33.5 最高、20.1 第二 → 两条 covered → closed。
只给"美国两组高于其他国家" → partial；说成"有保险更高" → contradicted。

**bar_78**：主干是 WeWork 高估值 vs Regus 盈利，但 `in_table=false`（表里只有 2013–2017 五个数）。
复述只能推出年度值 → 没有可比的 thesis → `off_table`。这不是 intent 写错，是这条 clip 不能进 V1。

#### 防循环与成本

- Agent A 建主干（不看 intent）；Agent B 复述（不看旁白）；Agent C 只拿两份 claim 列表对齐（看不到原片）。
- 人只裁决 C 判不了的分歧（50 条抽样）。
- 主干是每条 clip 的一次性资产（340 条跑一次）；之后每换一版 intent 只需重跑"复述 + 对齐"两次调用。

## 2. G1 的质量评估

G1 不按"固定命题"评，而按"要求 + 接受路径"评。

| 维度 | 具体指标 | 谁算 | 判定方式 |
|---|---|---|---|
| 映射完整 | 每条 requirement 至少对应一条 G1，每条 G1 有 requirement_id | 机器 | 双向映射检查 |
| 可判定 | 每条单元能单独判成完成/未完成 | 人抽检 | 二元判断练习 |
| 路径充分 | accepted routes 足以证明该要求 | 人审 | 见下方 bar_27 反例 |
| 反例覆盖 | 每条有具体 reject，覆盖只念数/只下结论/错单位 | 机器 + 人 | reject 非空 + 抽检 |
| 数据可追溯 | basis 每个值能在表里查到，或写明算式 | 机器 | 值匹配 + 算式存在 |
| 无重复 | 同一 requirement 内没有共享同一组数据的多条单元 | 机器 | basis 集合去重 |
| 一致性 | 两名标注者独立建 G1，报 κ / α | 人 | 双标注 |
| 稳定性 | 同一 intent 跑两次，单元/要求数是否一致 | 机器 | 两次运行比对 |

**路径充分的典型反例**：bar_27 若要求"分数随收入档上升"，只接受首尾 890/1150 是错的——
端点不能证明中间单调。要么检查完整序列，要么把要求改成"比较首尾"。

**效度检验（受控变体）**：

- 改一个关键数值 → G1 分应下降；
- 交换实体标签 → G1 分应下降；
- 删掉比较证据 → G1 分应下降；
- 延迟证据 → 只影响 G3，不影响 G1；
- 换配色/布局且仍可读 → G1 分不应下降。

这证明 G1 在测内容，而不是测格式。

## 3. 两层之间的关系

| intent 状态 | G1 状态 | 处理 |
|---|---|---|
| 不合格（泄露/范围不明/离题） | — | 先改 intent，不评 G1 |
| 合格但 off_table | — | 单独成桶，报数据缺陷率，不进主榜 |
| 合格 | G1 不合格 | 改 G1，不进入 baseline |
| 合格 | G1 合格 | 进入 baseline 评测 |

G1 的质量是**条件质量**：intent 不过关，G1 写得再好也没有意义。

## 5. 论文报告口径

**Intent**：泄露率、范围命中率、要求覆盖率、往返闭合率、人工通过率。

**G1**：要求映射完整率、路径充分率（抽检）、数据可追溯率、重复率、双标注一致率、稳定性。

**下游效度**：G1 分数与人工质量评分的相关性；受控变体的敏感度。

这组数回答两个问题：GT 本身靠不靠得住；模型分数是否真的对应视频质量，而不是格式相似度。

## 6. 执行顺序

0. 建主干：独立 agent/人只看旁白+图+表，输出 1–3 条 thesis 级 claim（不看 intent），340 条一次性完成。
1. 三个自洽例子（A/B 增长、bar_27 七档、单行占比）：公开要求 → 接受条件 → 合法替代 → 不合格反例。
2. 20 条试点：requirements → 一句话 → 覆盖检查 + 往返检查。
3. 50 条人工抽检：五条验收 + pass/revise/drop。
4. 全量 340 条：机器闸全跑，模型往返全跑，人工只介入 `revise` / `off_table`。
5. 冻结 GT 版本，再开始 baseline 评测。
