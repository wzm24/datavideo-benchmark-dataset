# 我们的位置：与 Text2Vis / DataNarrative / DataReel 的对照

更新：2026-09-23

## 0. 三个词先分清

| 词 | 含义 | 能否判对错 |
|---|---|---|
| **答案键 / GT** | 每题的**标准答案**（如某个数值、某个可执行事实） | 能，直接比对 |
| **参考资产** | 原视频、参考解说、原始截图、抽取 SVG | 不能，只用于起草候选与诊断 |
| **评分标准 / rubric** | 打分维度与档位描述（如 Narrative Quality 0–5） | 只能给分，不能判对错 |

> 关键事实：**Text2Vis 有答案键；DataNarrative 和 DataReel 没有逐条答案键**，它们只有"参考资产 + rubric"。我们的协议价值在于把答案键显式化、分层化。

## 1. 四者逐项对照

| 维度 | Text2Vis (Rahman 2025) | DataNarrative (Islam 2024) | DataReel (2026) | **我们（协议 + 扩展）** |
|---|---|---|---|---|
| 任务 | 表 + 问题 → 文字答案 + 可视化代码 | 表 → 数据故事（大纲+叙述+图表） | 表 + 意图 + 时长 + 风格参考图 → 可执行 HTML/D3 + 字幕 | 表 + schema + 意图 + 受众 + 时长 + 约束（+ 可选脱敏风格参考）→ 代码 + 旁白 + manifest |
| 每条的答案键 | ✅ gold answer + gold code + annotated chart | ❌（仅"黄金参考故事"） | 部分：**数据表是事实真值**；表达无答案键 | ✅ **G0 事实**（可执行表达式 + 期望值 + 单位） |
| 必须呈现的内容 | ❌ 不规定 | ❌ | ❌ | ✅ **G1 必需单元 + 权重 + 可接受路径** |
| 视觉证据要求 | ❌ | ❌ | ❌（只看 judge 印象） | ✅ **G2 逐单元证据规则** |
| 时间 / 音画同步 | —（静态图） | ❌ | 仅 pairwise 的一个维度 | ✅ **G3 时间政策 + SyncOffset** |
| 参考资产定位 | 图表标注用于人工核对 | 原文章故事 | 原视频截图作**输入**（附录 G 明说） | 参考资产只作起草/诊断，**不作输入**（除非脱敏） |
| 评测对象 | 答案文本 + 代码 + 人工图 | 两个系统的故事 | HTML 源码 + 渲染视频 | **代码层 + DOM 层 + 像素层** |
| 主要手法 | 多分量客观指标 + Final Pass Rate | pairwise（自动 + 人工 1–5） | LLM judge 0–5 四维 + pairwise | 客观指标 + 逐单元核验 + judge + 人工校准 |
| 容差 | 隐含（judge 判 answer match） | 无 | 无 | ✅ **两类**：测量误差 / 数据不确定（后者不扣模型分） |
| 可执行性 | ✅ Code Execution Success | ❌ | 有 JS 错误率，但不含动画问题 | ✅ RenderSuccess + 三层采集 |
| 评测器验证 | ✅ 236 条人工复核，差异 <15%；$2 / 1985 条 | 人工 1–5，100 条、2 位标注者 | 人类 pairwise，κ=0.58；VLM 与人类 76.7%/74.7% | 规划中：分层抽样 + 同 rubric + 报偏差；McNemar 配对检验 |

## 2. 从三篇各取什么

| 取什么 | 来源 | 用在哪 |
|---|---|---|
| **答案键思维**：可执行事实 + code execution success + pass rate | Text2Vis | 我们的 G0 + RenderSuccess + Completion 指标 |
| **评测器有效性证明**：分层抽样、同一 rubric、报告自动与人工的偏差（目标 <15%） | Text2Vis | G4 人工验证集与 judge 校准 |
| **成本与规模声明**：条数 / 分钟 / 美元 / 每分每美元 | Text2Vis | 主表成本列、Q4 成本收益分析 |
| **配对显著性检验**（McNemar） | Text2Vis | baseline 之间的显著性 |
| **成对比较（Win/Tie）**：避免绝对刻度漂移 | DataNarrative / DataReel | **同一输入档内**的系统对比 |
| **多标准 1–5 + 明确档位描述** | DataNarrative | 我们的主观质量维度（逐档写清描述） |
| **意图作为输入、0–5 四维 judge、pairwise + κ** | DataReel | 主榜的基线形态与可比性 |
| **抽取数据的人工审计纪律**（50 张审计、偏差范围） | DataReel | 我们 G0 的 `dataset_uncertainty` 与数据质量报告 |

## 3. 我们保留的差异（论文卖点）

1. **逐单元视觉证据**（G2）：从"整体 1–5"升级为"U1/U2/U3 是否真的被画出来"
2. **时间政策 + SyncOffset**（G3）：他们完全没有时间维度（DataReel 只用一个 pairwise 维度）
3. **程序化几何核验**：从 DOM/像素反算，带 `model_tolerance`；他们交给 judge
4. **事实 precision（含额外断言）+ 两类容差**：他们只有 answer match，不区分多说/少说，也不谈容差
5. **输入契约与责任分层（B1–B5）**：他们只有一个输入设置
6. **中间态监督数据**：340 条五件套（关键帧 + structure-aware SVG + 数据表 + narration + intent）

## 4. 一句话差异声明（可放摘要第二句）

> 与把数据视频当作理解对象的基准、以及只给出参考资产与主观 rubric 的生成基准不同，我们为生成任务提出**分层答案键**：可执行的数据事实（G0）、必须呈现的语义单元及其权重（G1）、视觉证据规则（G2）、相对生成旁白的时间政策（G3），并用人工验证集（G4）校准自动评测器。
